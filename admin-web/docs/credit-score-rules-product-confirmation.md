# 信用分规则产品确认清单

## 一、文档目的

本文件依据原型文件 `Prototype/excel/信用分规则.xls` 整理，用于确认信用分规则是否可以直接转化为系统自动计算逻辑。

当前 Excel 已经明确了部分业务规则，但仍有一些条件、边界和执行口径没有完全定义。请产品经理确认以下内容后，研发再进行数据库设计、规则引擎和信用分流水开发。

## 三、需要产品确认的内容

### 3.1 规则适用对象

请为每条规则明确适用对象：

- 老板
- 零工
- 双方

例如：

- “零工好评”是给老板加分，还是给零工加分？
- “零工差评”是扣老板的分，还是扣零工的分？
- “雇主原因取消订单、拖欠报酬、飞单”是否只影响老板信用分？

### 3.2 触发事件和触发时机

请明确每条规则由哪个系统事件触发，以及何时计算：

- 订单完成时
- 老板完成结算时
- 零工提交评价时
- 投诉审核成立时
- 飞单人工认定成立时
- 申诉失败后

同时确认：

- 同一个事件是否只允许计算一次？
- 订单状态重复回调时是否需要幂等处理？
- 规则计算失败时是否自动重试？

### 3.3 区间分值的具体映射

以下规则只有扣分区间，系统无法自动选择具体分值，需要提供明确的条件映射。

#### 雇主原因取消订单

请确认以下边界和分值：

| 取消时机 | 建议确认分值 |
| --- | ---: |
| 开工前 16 小时以上 | -2 |
| 开工前 4～16 小时 | -5 |
| 开工前 1～4 小时 | -10 |
| 开工前 1 小时内 | -20 |
| 零工已经到达后取消 | -20 |

需要确认“刚好 1 小时、4 小时、16 小时”分别属于哪一档。

#### 超时结算

每天日结当前描述为：

- 超过 24 小时且不超过 48 小时：扣 5 分
- 超过 48 小时：扣 10 分

请确认：

- 刚好 24 小时是否扣分？
- 刚好 48 小时属于 -5 还是 -10？
- 以完工时间、签退时间还是订单完成时间作为起算点？

#### 零工投诉、拖欠报酬、飞单

请提供明确的违规等级和对应分值，例如：

| 违规等级 | 判定条件 | 分值 |
| --- | --- | ---: |
| 一般 | 具体条件 | -20 |
| 较重 | 具体条件 | -50 |
| 严重 | 具体条件 | -100 |
| 特别严重 | 具体条件 | -200 |

其中拖欠报酬和飞单目前最高扣分分别为 1000 分，需确认是否一次性扣除，还是分多次执行。

### 3.4 金额条件

请确认：

- “金额大于 20 元”是否不包含 20 元？
- 使用订单工资、实际结算金额，还是扣除平台费用后的金额？
- 压薪日结使用订单总金额还是每次结算金额？
- 金额为 20 元时是否不加分？

### 3.5 近 90 天完单率

请明确完单率的计算口径：

- 分母是报名订单、录用订单，还是已开始工作的订单？
- 分子是完成订单数还是完成结算订单数？
- 老板取消、零工爽约、平台取消是否计入分母？
- 至少完成多少单后才计算完单率？
- 90 天是滚动 90 个自然日，还是固定统计周期？
- 达到 90% 后额外加 3 分，是每完成一单加一次，还是每个统计周期只加一次？

### 3.6 评分上下限和重复计算

请确认：

- 初始信用分是多少？当前是否为 100 分？
- 最高信用分是多少？
- 最低信用分是否允许低于 0 分？
- 同一订单是否可以同时触发多条规则？
- 同一订单是否可以同时触发“完成订单”和“及时结算”？
- 同一违规每天、每月或每个订单是否有次数上限？
- 同一投诉、拖欠或飞单是否只能处罚一次？
- 信用分变化是否立即生效？

### 3.7 评价规则

请明确：

- “好评”和“差评”分别对应几星？
- 评价是否允许修改？修改后是否回滚原信用分变化？
- 评价被删除、申诉成功或判定无效后如何处理？
- 双方互评是否都会影响信用分？

### 3.8 投诉、拖欠报酬和飞单

这些规则不能仅依靠订单状态自动判定，需要人工审核或风控结果。

请补充：

- 谁负责确认违规成立？
- 需要哪些证据？
- 是否需要二次审核？
- 申诉成功后是否自动恢复信用分？
- 处罚记录是否需要关联订单、投诉单或申诉单？
- 同一事件是否允许重复提交和重复处罚？
- 处罚分值由系统固定，还是由审核人员选择等级？

### 3.9 结算方式编码

请确认 Excel 中的结算方式与系统编码的对应关系：

| Excel 名称 | 系统编码（待确认） |
| --- | --- |
| 每天日结 | `daily` |
| 压薪日结 | `heldBack` |
| 全平台 | `all` |

如果系统已有其他编码，请产品和研发统一一套名称，避免规则匹配失败。

## 四、建议研发落地的数据结构

确认完成后，建议将 Excel 规则拆成结构化数据，而不是只保存成规则说明文本。

每条可执行规则至少需要以下字段：

| 字段 | 说明 |
| --- | --- |
| `ruleCode` | 唯一规则编码 |
| `ruleName` | 规则名称 |
| `userType` | 适用对象：老板/零工 |
| `settleType` | 适用结算方式 |
| `eventType` | 触发事件 |
| `condition` | 结构化条件或条件参数 |
| `scoreChange` | 加分或扣分值 |
| `scoreMin` / `scoreMax` | 分值区间（如确实需要人工选择） |
| `oncePerOrder` | 是否每个订单只执行一次 |
| `dailyLimit` / `monthlyLimit` | 次数限制 |
| `enabled` | 是否启用 |
| `effectiveTime` | 生效时间 |
| `description` | 给后台展示的规则说明 |

另外还需要一张信用分流水表，记录：

- 用户 ID
- 规则编码
- 关联订单/投诉/申诉 ID
- 变更前分数
- 分值变化
- 变更后分数
- 操作时间
- 操作来源（自动计算/人工审核/申诉回滚）
- 操作人
- 幂等业务号

## 六、结论

这份 Excel 可以作为信用分规则的产品基准和初始数据来源，但目前还不能无歧义地直接转换成自动计算程序。

研发可以先落地规则管理、规则展示和结构化规则配置；待产品补齐触发条件、区间映射、边界、幂等、上限下限及人工审核口径后，再启用自动加减分。

## 七、已确认及默认执行口径

以下口径作为当前版本的开发基线：

### 7.1 时间和比例边界

- 完单率达到 90% 即满足条件，按 `>= 90%` 计算。
- 24 小时、48 小时、72 小时均按包含边界处理。
- 为避免区间重叠，边界命中时采用处罚更重的一档：
  - 超时结算：`24 小时 <= 时长 < 48 小时` 扣 5 分，`时长 >= 48 小时` 扣 10 分。
  - 拖欠报酬：`待结算时长 >= 72 小时` 视为拖欠。
  - 取消订单：为避免原表条件重叠，按连续区间执行：`<= 1 小时` 扣 10 分，`> 1 小时且 <= 4 小时` 扣 5 分，`> 4 小时且 <= 16 小时` 扣 2 分，`> 16 小时` 不扣分；零工到达后取消优先按到达后规则扣 20 分。

### 7.2 老板信用分默认口径

- 老板信用分规则只作用于老板账号。
- 初始分为 0 分。
- 订单完成、及时结算、评价等规则按订单或评价业务号幂等执行一次。
- “完成订单”按实际结算成功事件触发，订单金额必须大于 20 元。
- 近 90 天完单率按已完成订单数除以“待结算 + 已完成”订单数计算，包含统计当天。
- 同一订单可以同时获得“完成订单”和“及时结算”两项加分。
- 投诉、拖欠报酬、飞单在审核确认成立后执行，分别关联投诉单、订单或处罚单。
- 拖欠报酬每个订单扣 100 分，每自然月累计最多扣 1000 分。
- 飞单按自然月累计次数分档：1 单扣 100 分，2～5 单扣 300 分，6 单及以上扣 1000 分。

### 7.3 零工星级分默认口径

- 零工星级分规则只作用于零工账号，初始分为 0 分。
- “奖励星级分”采用规则描述中的“自然月完成率达到 95%（含）加 300 分”；触发时机栏中关于“5 星评价加 5 分”的内容视为原表复制错误。
- 工时星级分在订单确认完工后计算，按完整 60 分钟计分，不足 60 分钟的部分舍弃；城市淡旺季系数取订单完工时的有效系数。
- 好评星级分按每个有效好评加 100 分；评价被撤销或申诉成功时，回滚对应流水。
- 差评按单个订单一次扣 10 分。
- “投诉”采用规则描述中的“核实后星级分清零”；分值栏中的“扣 20 分”作为原表冲突项，不再另行扣 20 分。

### 7.4 评分上下限和历史数据

- 当前版本暂不设置正向上限，但老板信用分和零工星级分均不得低于 0 分。
- 所有规则执行必须有唯一幂等业务号，重复任务不得重复加减分。
- 规则生效前的历史订单不追溯计算。
- 规则调整只影响生效时间之后的新事件，已经产生的信用分流水不自动重算。
- 申诉成功时通过反向流水恢复原分值，不直接修改历史流水。

### 7.5 定时任务和人工审核

- 订单类规则在订单事件发生后执行；周期类规则按中国标准时间（Asia/Shanghai）执行。
- 日统计任务每天凌晨执行，周统计任务每周一凌晨执行，月统计任务每月 1 日凌晨执行上月数据。
- 定时任务失败可重试，但必须使用同一幂等业务号。
- 投诉、拖欠报酬、飞单必须经过平台审核确认后才产生扣分；审核人、审核时间、证据和关联业务单号需要写入流水。

如产品经理没有异议，以上内容可作为研发实现基线；后续若修改任一口径，需要同步调整规则配置、测试用例和历史数据处理策略。
